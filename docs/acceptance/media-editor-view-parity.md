# RC4 편집·글보기 미디어 동등성 검증

> 2026-09-01 후속 감사에서 업로드 MP4를 항상 16:9 외곽에 표시하는 결함을 확인했습니다. 현재 미출시 변경은 실제 MP4의 디코딩 크기로 에디터·글보기 외곽 비율을 동일하게 맞춥니다. 180×320 fixture를 1280×900과 390×844에서 확인했고 가로 넘침 없이 각각 같은 원본 비율을 유지했습니다. 실행 시 계산한 style·class는 canonical HTML에 저장하지 않습니다. 이 후속 결과는 기존 `0.1.0` 배포 증거에 포함되지 않습니다.

검증일: 2026-08-31. 범위는 YouTube·Vimeo·업로드 MP4의 편집·조회 표시 통일입니다.

## 구현 결과

- 편집 NodeView와 글보기에서 같은 플레이어 생성 코드와 설정을 사용합니다.
- 새 기본값은 즉시 표시, 자동재생 OFF입니다. 기존 명시적 클릭 후 로드 설정은 보존합니다.
- 같은 사이트 업로드 MP4는 외부 연결 제한 설정과 무관하게 즉시 표시합니다.
- 편집기의 선택·삭제 버튼은 플레이어 바깥에만 배치합니다. 저장 HTML에는 들어가지 않습니다.
- 저장 정본은 기존 `figure > a` 구조 그대로이며 iframe·video·버튼·SVG를 DB에 저장하지 않습니다.

E2E의 업로드 API는 프로토콜 모형입니다. 실제 업로드·저장·재생 증거는 별도로 전용 G7에서 수집했습니다.
YouTube·Vimeo는 실제 제공자의 썸네일·컨트롤 표시까지 확인했으며, 외부 영상의 재생 시간 증가까지 검증했다고 표현하지 않습니다.

원시 증거는 `.build/rc4-media-proof/`의 브라우저·서버 JSON 및 PC·모바일 스크린샷입니다.
검증 번들 SHA-256: `c2ea132204022dd606f281dcbd9f0bbe29b6a0060f4ecdc59065ad46c1d39720`.

## 패키지·배포 경계

이번 검증은 전용 G7의 RC3 설치 위에 RC4 개발 코드를 동기화한 개발 검사입니다.
RC4 ZIP 설치, 릴리스 전체 게이트, 공유 테스트 사이트 및 운영 배포는 수행하지 않았습니다.
기존 RC3 배포 증거를 RC4 증거로 재사용하지 않습니다.
다음 배포에서는 새 RC4 패키지로 릴리스 게이트를 통과하고, 플레이어 즉시 표시가 필요한 사이트의 기존 클릭 후 로드 설정도 명시적으로 변경해야 합니다.
