# 기본 편집 기능 실제 QA 및 수정 — 2026-09-02

## 결론과 범위

기본 편집 기능을 실제 게시판에서 조작하고 저장·조회·재편집했습니다. 이 과정에서 **조회 화면 서식, 글자색·강조색 우선순위, 체크리스트 표시, 체크 완료 상태 상속** 결함을 발견해 수정했습니다. 수정 커밋은 `b7fd166`입니다.

후속 업로드 검증은 사용자 브라우저와 분리된 **헤드리스 Google Chrome**에서 실행했습니다. 사용 중인 Edge 조작과 사용자에게 파일 선택을 요청하는 방식은 중단했습니다. 테스트는 에디터 전용 G7 체크아웃·QA 계정·QA 글을 사용하며 G7 코어와 Page Builder를 수정하지 않았습니다.

이번 결과는 **구현·테스트 결과이며 새 릴리스나 운영 배포 완료가 아닙니다.** 기존 `0.1.0` stable 이력 및 이미 배포된 `0.1.1-rc.1`과 이번 미배포 수정본을 구분합니다.

문서 시각 기준에 따라 제목·인용·표·목록을 두 화면의 공통 규칙으로 정리했습니다. 표 셀 정렬과 테두리, 다크 모드 색상도 함께 비교했습니다. HTML 저장 정책이나 허용 태그·속성 범위는 확장하지 않았습니다.

자동 검사는 내용 문자열 존재 여부만 비교하지 않습니다. 본문이 실제 편집 가능하고 레거시 경고에 가려지지 않았는지, 제목 크기·색상·행간·체크리스트·표 셀의 계산된 스타일이 올바른지도 검사합니다. 이 증거가 없거나 양쪽 모두 잘못된 값이면 릴리스 증거 검증기가 거부합니다.

## 실제 UI 확인

### 공유 로컬의 기본 서식 QA

배포된 기존 후보에서 QA 글 **17**을 생성해 다음 조작을 수행하고 저장·조회·재편집을 비교했습니다. 이 관찰에서 위 결함을 발견했으며, 공유 로컬에 이번 수정본을 덮어쓰지는 않았습니다.

- 굵게·기울임·밑줄·취소선, 글자 크기, 색상·강조색, 서식 지우기.
- 제목 2/3/4, 인라인 코드, 위·아래 첨자, 가운데 정렬, 행간, 들여쓰기·내어쓰기.
- 인용, 글머리·번호·중첩 목록, 체크리스트, 코드 블록, 구분선.
- 정상/거부 링크, 표 생성, 행·열 추가/삭제, 머리글, 셀 합치기/나누기·스타일.
- 찾기·바꾸기, 실행 취소/다시 실행, 전체 화면·Escape.
- 제목만 입력 후 Enter: 본문 입력 안내, 제목 보존, 페이지 이동 없음.

일부 최초 조작에서 macOS의 커서 이동 키를 잘못 사용했습니다. 해당 조작은 통과 근거에서 제외하고 올바른 선택 위치로 다시 확인했습니다. 자동 검사도 DOM 선택과 편집기 모델 선택이 일치한 뒤 Enter를 입력하도록 보완했습니다.

### 전용 G7 + 독립 헤드리스 Chrome

현재 수정 번들을 전용 테스트 설치본에만 반영했습니다. 실제 QA 계정으로 로그인하고 파일 선택 UI와 드롭 이벤트를 통해 서버 업로드 후 QA 글 **254**를 저장했습니다. 업로드 응답을 모킹하거나 DB에 본문을 직접 넣지 않았습니다.

| 항목                | 관찰 결과                                                                                          |
| ------------------- | -------------------------------------------------------------------------------------------------- |

| 본문으로 PNG 드래그 | 추가 업로드 후 저장·재편집에서 이미지 3개 유지                                                     |

| MP4 파일 선택       | 세션 생성 `201` → 청크 `200` → 완료 `201`, 원래 `playable-portrait.mp4` 이름 유지                  |

| 서버 저장 정본      | 이미지 3개·미디어 노드 1개, `video/iframe/script` 태그 0, inline style 0, 실행 전용 미디어 class 0 |

확장자가 없는 내부 해시 URL과 원래 다운로드·표시 파일명은 구분합니다. MP4의 원래 파일명과 MIME, Range 응답은 유지됐습니다.

영상 비율은 메타데이터를 실제로 읽은 뒤 측정했습니다. 최초 로딩 직전 screenshot을 재생·비율 통과 근거로 사용하지 않습니다. 1×1 검은 PNG fixture가 검은 정사각형으로 보이는 것은 영상이나 플레이어가 아닙니다. headless 재생 시간 증가는 디코딩·재생 증거이며 실기기에서 재생 버튼을 누른 증거로 표현하지 않습니다.

전용 설치본의 `autoEmbedUrls`는 미설정이며 템플릿 기본값이 OFF입니다. 이 상태에서 직접 입력한 YouTube URL + Enter가 일반 링크로 남는 것을 확인했습니다. **실제 G7에서 자동 변환 ON 상태까지 이번 수동 QA로 확인했다고 주장하지 않습니다.** ON 상태의 변환·실패·원문 보존은 별도 자동 회귀 검사에서 확인합니다. 테스트를 위해 공유 환경 설정을 임의로 변경하지 않았습니다.

### 온라인 읽기 전용 확인

배포된 후보에서 기존 글 **1850012**의 업로드 MP4를 조회·편집 화면에서 확인했습니다. 실제 영상은 720×1280, 표시 크기는 양쪽 모두 약 416×739.55px였습니다. 조회 화면에서 재생 시간이 13.36초까지 증가하고 일시 정지되는 것을 확인했습니다. 이 글을 수정·저장하거나 새 파일을 업로드하지 않았습니다.

플러그인 관리 화면에서는 기존 후보 활성·CKEditor 비활성을 확인했습니다. 이것을 이번 수정본 배포나 온라인 전체 기능 검증으로 확대하지 않습니다.
