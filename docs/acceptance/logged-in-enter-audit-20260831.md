# 로그인 상태 제목 Enter 검증

검증일: 2026-08-31. 이번 작업은 진단·실제 로그인 테스트이며 기능 수정이나 배포가 아닙니다.

## 결론

Chrome에서 기존 전용 QA 계정으로 로그인하여 공개·관리자 글쓰기의 제목 Enter 새로고침을 모두 확정 재현했습니다. 제목이 쿼리 문자열에 포함된 GET 문서 요청으로 현재 페이지가 다시 열리고, 제목이 비워지며 본문 필수 안내는 나오지 않았습니다. 이 결함은 아직 수정·배포되지 않았습니다.

반면 공개 등록 버튼 클릭과 관리자 저장 버튼에서 Enter 입력은 저장 API에 POST를 보내고 422 응답으로 빈 본문을 거절하며 제목을 유지했습니다. 키보드 입력 자체가 작동하는 양성 대조까지 확인했습니다.

## 환경

- 사용자 일반 저장소·공유 사이트와 분리된 전용 G7 7.0.9
- 공개 템플릿 1.1.2, 게시판 모듈 1.1.0
- 설치 등록 버전 RC3 위에 미디어 표시 RC4 개발 코드 적용
- 소스 기준: `63cb7d4`
- 기존 전용 QA 계정 로그인 후 공개·관리자 작성 화면에서 검사

| 관리자 제목 Enter          | `GET /admin/board/free/create?title=...` → 문서 200·페이지 탐색, 제목 유실, 본문 안내 없음 | 결함 재현                   |
| 공개 등록 버튼 클릭        | 게시판 저장 API POST → 422, `내용은 필수입니다.`, 제목 유지                                | 정상 차단                   |

Chrome의 실제 키 입력과 문서 탐색·요청 이벤트를 함께 수집했습니다. 헤드리스 Chrome 실행 결과가 아니라 연결된 Chrome에서의 결과입니다. 이벤트 페이징 누락·잘림은 없으며, 증거에는 요청 헤더·인증정보를 저장하지 않았습니다.

## 원인 및 수정 범위

공개·관리자 폼에 공통 submit 처리가 없고, 저장 버튼의 click 처리에만 API 저장이 연결돼 있습니다. 제목에서 Enter를 누르면 브라우저 기본 GET 제출로 빠져 서버의 본문 필수 검증 경로 자체에 도달하지 않습니다. 빈 본문을 서버가 정상 저장한 현상과는 구분합니다.

- 공개 폼: `templates/sirsoft-basic/layouts/partials/board/form/_post_form.json`의 루트 Form에는 submit action이 없고 등록 버튼은 `type=button` 및 click action입니다.
- 관리자 폼: `modules/sirsoft-board/resources/layouts/admin/admin_board_post_form.json`의 `post_form`에도 submit action이 없으며 저장은 별도 버튼에 연결됩니다.
- 정상 기준: 제목 Enter에서 페이지를 유지하고 제목을 보존하며 빈 본문 안내·본문 포커스를 제공해야 합니다. 등록 버튼과 동일한 저장 검증을 통과해야 합니다.
- G7 코어·번들 직접 수정 금지 원칙을 유지합니다. 게시판 공통 폼 수정과 플러그인 연동 대응의 범위를 분리해야 하며, 이번 진단에서는 어느 쪽도 수정하지 않았습니다.

내장 브라우저의 자동 Enter는 일반 버튼의 기본 동작도 실행하지 못했으므로 정상 판정에 사용하지 않았습니다. 컴퓨터 제어 보완도 Codex 앱 제어 제한으로 실행하지 못했습니다. 이후 제품 소유자의 Chrome 검증 승인에 따라 위 최종 검사를 수행해 제보를 재현했습니다.
