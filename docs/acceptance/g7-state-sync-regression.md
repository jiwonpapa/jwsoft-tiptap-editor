# G7 제출용 본문 동기화 보완 — 2026-08-31

## 구현 및 확인 결과

- 본문 동기화의 300ms debounce는 유지하고 공개 `state.setLocal`의 `render:true`로 제출용 폼 스냅샷도 갱신합니다. G7 코어·번들 템플릿·게시판 모듈은 변경하지 않았습니다.
- 현재 에디터 소스와 실제 G7 실행 번들·기본 게시판 저장 시퀀스를 함께 사용하는 DOM 통합 검사를 추가했습니다. 수정 전에는 너비 변경 뒤 제출 본문이 빈 문자열이어서 실패했고, 수정 후에는 아래 5개가 통과했습니다.
  - 신규 글의 일반 저장
  - 신규 글의 화면 너비 변경 후 저장
  - 수정 글의 화면 너비 변경 후 저장
  - 입력 직후 저장 시 debounce 반영
  - 다국어 본문 저장 및 다른 언어 보존
- 에디터를 G7이 렌더링하는 DOM 안에 배치해 선택 위치·DOM 연결·에디터 instance가 유지되는지도 확인했습니다.
- 전용 G7 통합 검사에 포함하여 소스 checksum으로 검증 증거를 연결했습니다.

## 후속 패키지 및 회귀 검증

- `make check`(단위 89개), 빌드, 전용 G7 통합 검사(기존 PHP 6개와 DOM 저장 시나리오 5개)가 통과했습니다.
- 기존 독립 Chromium UI 검사를 재실행해 21개 통과, viewport 비대상 13개 skip을 확인했습니다. 첫 실행에서 IME 검사의 이전 `render:false` 기대값이 실패하여 `render:true` 계약으로 갱신했습니다. 한글 조합·붙여넣기·실행취소·다시실행 및 최종 본문 동등성 검사는 유지했습니다.
- 새 RC1 ZIP은 두 번 생성한 SHA-256이 `2e22fd25aad73e9d716f47e57467de69975694d48c78ca58c535ddd4ddcacb14`로 같았으며, 라이선스 및 자체 호스팅 패키지 검사가 통과했습니다. 이전 RC1 ZIP과 실패 기록은 별도 보존했습니다.

- 위 전환 전후 페이지 8건·게시글 215건·상품 100건, 총 323건의 본문 해시와 이미지·미디어 업로드 테이블의 행 수가 동일했습니다. 기존 G7 코어 변경 상태도 보존했습니다.
- 이 시점의 최신 증거는 **51/62**입니다. 남은 11개는 실제 G7 화면 6종, 후보 공개 후 GitHub 수명주기 3개, staging·production 배포 2개입니다. 독립 UI 통과를 실제 G7 화면 검증으로 대체하지 않았습니다.

## 아직 증명하지 않은 범위

DOM 통합 검사는 인증·HTTP 저장·DB 쓰기를 하지 않으며, 독립 UI 검사는 G7 상태 API를 대체한 테스트 환경입니다. 실제 사이트의 저장·재조회, 전체 폼 재렌더 성능, 실제 G7 재렌더 중 한글 조합 입력 및 이미지 전용 글의 최종 회귀를 대신하지 않습니다. 앞선 사용자 실기기 확인 역시 이번 소스 변경 이후의 재검증 결과로 재사용하지 않습니다.

인증된 실제 화면 검증은 로그인 권한 확인으로 중단했으며, 다른 계정·API 경로로 우회하지 않았습니다. 전용 로컬 QA 로그인·테스트 글 작성 및 수정 승인 이후 현재 패키지로 6종 화면을 재검증해야 합니다. 따라서 RC 공개·staging·production 배포 및 62/62 승인은 여전히 미완료입니다.

기존 실패 기록은 [RC1 로컬 검증](g7-rc1-local-validation.md)에 그대로 보존합니다. 새 검사 통과를 과거 실패 기록의 통과 전환으로 사용하지 않습니다.
