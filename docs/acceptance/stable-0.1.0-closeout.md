- 정식 버전 `0.1.0`, 공개 태그 `v0.1.0`.
- 릴리스 ZIP SHA-256 `30828d200d22ae2978efa2652a2e33dac502ada8b176e98a197a16c82718abf7`.
- 후보 57/57 → 공개 GitHub 설치 생명주기 60/60 → local staging 61/61 → production 최종 62/62 순서로 통과.
- GitHub Release asset, staging, production에 같은 ZIP 바이트를 사용함.
- 두 배포 대상 모두 JWSoft `0.1.0` active / CKEditor inactive이며 설치·활성화만으로 기존 본문을 변경하지 않음.

## 실제 기능 검증

- 인증된 Chrome에서 공개·관리자 게시판 작성/수정/답글, 상품 한영 설명, 페이지 작성/수정/공개 출력을 저장 후 다시 열어 확인함.
- 이미지 파일 선택기·업로드·저장·재조회, 잘못된 이미지 거부와 재시도 실패 처리를 확인함.
- MP4 청크 업로드, `.mp4` 파일명 보존, 편집/조회 양쪽의 controls·실제 재생·HTTP Range `206`을 확인함.
- YouTube 즉시 플레이어, X·Facebook 화이트리스트 공식 게시물, 제공자 실패 시 원본 URL 보존을 확인함.
- 제목 Enter와 빈 본문을 공개/관리자 작성·수정·답글 18개 HTTP 경로에서 `422`로 거부하고 기존 저장 해시가 보존됨을 확인함.
- 390×844 다크 모드에서 툴바와 본문 가로 넘침이 없고 각 편집 화면에 instance가 하나만 생성됨을 확인함.

## 배포 검증

- local staging은 DB·플러그인 백업 후 동일 버전을 재적용했고 게시판 15건, 페이지 8건, 상품 1건과 관련 모듈 테이블·모듈 목록 해시가 전후 동일함.
- production은 DB·플러그인 백업 후 RC4에서 stable로 갱신했고 게시글 50,014건, 페이지 6건, 상품 20,000건 등 본문 70,020건과 설정 해시가 전후 동일함.
- production 설치 파일 7개와 공개 플러그인 합본의 실행 JS가 릴리스 입력과 일치하고 홈·health·관리자 로그인 smoke가 모두 HTTP 200임.
- DB·플러그인 백업과 상세 JSON 증거는 비밀값을 제외한 로컬 배포 증거 디렉터리와 대상 서버의 제한된 임시 경로에 보존함.

## 동결된 범위

Office 문서 가져오기, 실시간 공동 편집, AI 작성, 페이지 빌더, 임의 외부 HTML·스크립트 삽입, 기존 CKEditor 본문 일괄 변환은 이 제품 범위가 아님. 기존 글은 JWSoft에서 수정 후 저장할 때만 지원하지 않는 레거시 서식이 정제될 수 있음.

X·Facebook 본문은 공식 SDK가 접근 가능한 공개 게시물에서만 표시되며 제공자 차단·삭제·rate limit은 성공으로 위장하지 않고 원본 URL을 유지함. Android/iOS 물리 키보드 입력은 자동화된 stable 승인 범위 밖의 별도 호환성 관찰 항목임.
