# 실제 기능 결함 4차 개선

기준 감사: [RC1 실제 기능 감사](g7-feature-audit-20260831.md). 각 차수는 코드·자동 검사·실제 G7·배포를 구분합니다. 다른 제품이나 G7 코어는 변경하지 않습니다. 이 문서는 진행 기록이며 최종 배포 완료 선언이 아닙니다.

## 1차 — 의미상 빈 본문과 빠른 삭제 동기화

- 서버 정제 뒤 공백·NBSP·제로폭 문자·빈 문단/표만 있는 HTML을 `''`로 정규화합니다. G7의 기존 필수/선택 규칙을 그대로 적용합니다. 상품 설명·페이지·비어 있는 번역에 새로운 필수 조건을 추가하지 않습니다.
- 이미지 전용 본문과 영상/카드의 유효한 정제 본문은 유지합니다. 정책 확인 토큰이 있어도 빈 게시글 필수 검사를 우회하지 못합니다.
- 지연 동기화가 끝나기 전에 입력을 원래 값으로 되돌릴 때, 과거 스냅샷과 같다는 이유로 최종 변경을 버리지 않도록 수정했습니다.
- `make check` 통과: 단위 103건. `make build` 통과. `make integration-check` 통과: 실제 G7 엔진을 사용하는 상태 동기화 7건 포함.
- 전용 G7의 실제 인증 HTTP 18건(공개/관리자 × 등록/수정/답글 × 빈 문단/보이지 않는 공백/빈 표)이 모두 422 `errors.content`로 거부됐습니다. 전후 게시글 본문 해시 동일. 검사 토큰은 종료 시 폐기합니다.
- 실제 공개 글쓰기에서 제목만 입력한 등록과 키보드 입력→전체 선택→Backspace→등록 모두 `내용은 필수입니다`로 차단. 빈 에디터 DOM과 0자 표시도 확인했습니다.
- 대조군 이미지 전용 글 232는 실제 등록·조회 성공, 이미지 `complete=true`, `naturalWidth=1` 확인(1px 시험용 PNG).
- 자동 브라우저 `fill('')`는 키보드 삭제와 달리 이전 입력을 제출하는 결과가 나와 실사용 통과 근거에서 제외했습니다. 그 과정의 QA 글 229~231은 증거로 남겼습니다. 실제 키보드와 G7 엔진 직접 회귀는 별도로 검사했습니다.
- 개발 설치 파일뿐 아니라 G7의 합본 자산에도 새 JS가 포함되는 것을 확인했습니다. 전용 호스트에서 공식 `plugin:cache-clear jwsoft-tiptap-editor`를 사용했습니다.

## 2차 — 공개/관리자 이미지 업로드와 오류 복구

- 공개 Basic의 이벤트 객체와 Admin Basic의 배열 알림을 정규화합니다. 불완전한 입력 알림을 무시하며 실제 파일 입력이 렌더되기 전/사라진 뒤에는 fallback 선택기를 유지합니다.
- `업로드 후 삽입`/`업로드 중…`으로 행동·상태를 표시하고 파일명·진행률·서버 처리 상태를 읽기 쉽게 표시합니다. 중복 호스트 이미지 압축은 제거했습니다.
- 공개 기본 업로더로 PNG 두 장을 실제 업로드→글 233 등록→조회→재편집. alt·제목·캡션·50% 크기와 실제 이미지 로드(1px/640px)를 확인했습니다.
- 관리자 기본 업로더로 같은 QA 글의 첫 이미지를 실제 업로드 교체→저장→조회. 이미지 두 장 모두 640px 로드, 변경 캡션 보존 확인.
- PNG 확장자의 비이미지 파일을 실제 서버에 업로드하여 거부→재시도→거부→선택 해제→모달 취소를 검사했습니다. 본문 이미지 삽입 0개, 열린 모달 0개.
- 이 오류 검사에서 번역 키가 표시되던 추가 결함을 발견해 수정했습니다. 프런트엔드 JSON 번역을 PHP 이름 공간에도 연결하여 현재 오류는 한국어 안내로 표시되며, 용량 매개변수도 치환됩니다.
- 큐 실패 후 재시도·성공 파일 재전송 방지·취소 뒤 늦은 응답·닫힌 모달·선택 해제 회귀를 추가했습니다. 실제 불안정 네트워크의 모든 패턴을 재현했다는 뜻은 아닙니다.
- 화면 증거: `.build/four-phase-repair-20260831/image-rejection.png`, `image-admin-saved.png`.
- `make check` 107건 및 `make integration-check` 통과. 손상 이미지의 깨진 미리보기는 이미지 아이콘으로 대체합니다.

## 3차 — 영상 업로드와 게시글 플레이어

- G7의 비동기 본문/동일 노드 재렌더를 관찰하여 조회 화면에 플레이어를 연결합니다. 에디터 내부 저장 구조는 canonical figure/link 그대로 유지합니다.
- 원본 파일명·MB/백분율·서버 확인 상태를 표시합니다. 한 파일의 내부 청크 수를 파일 개수처럼 표시하지 않습니다. 원본 링크와 감지 가능한 로드 오류의 재시도도 제공합니다.
- 실제 1,235,246바이트 MP4를 1MB 청크 설정으로 업로드하여 글 234 저장. 원래 `feature-audit-playable-20260831.mp4` 이름과 native controls/playsinline, 640px 영상·duration 12초를 확인했습니다. 실제 재생 후 currentTime=12/ended=true, 키보드 탐색도 확인했습니다.
- 로컬 MP4 구간 요청 bytes=0-1023은 HTTP 206, Content-Length 1024, Content-Range와 원본 파일명의 Content-Disposition을 반환합니다. G7 StorageInterface 경로·disk 계약을 통해서만 로컬 파일을 읽습니다. 원격 스토리지는 기존 스트리밍 계약을 유지하며 별도 원격 Range 실증은 하지 않았습니다.
- 글 225 YouTube는 실제 외부 플레이어의 제목·썸네일·재생 버튼까지 로드됐고, 글 226 Vimeo는 실제 외부 컨트롤·61초 길이까지 확인했습니다. 외부 iframe 생성/로딩과 실제 시간 증가 확인은 구분합니다. 공급자의 임베드 금지·로그인·광고 제한을 우회하지 않습니다.
- 자동 회귀: 늦은 본문/재렌더, 로드 오류 재시도, byte 단위 청크 재개, 중단 후 재시도 금지, HTTP Range와 경로 이탈 방어. 취소 검사에서 다른 realm DOMException이 일반 오류로 바뀌던 결함을 추가 수정했습니다.
- `make check` 단위 111건, `make build`, `make integration-check` 통과. 화면 증거: `.build/four-phase-repair-20260831/mp4-saved-playback.png`, `youtube-player.png`, `vimeo-player.png`.

## 4차 — URL/SNS 처리와 실제 기능 배포 gate

- 단독 URL을 직접 입력하고 Enter를 누르는 동작도 지원합니다. Shift+Enter·IME 조합 Enter·일반 문장·설정 OFF에서는 자동 변환하지 않습니다.
- 요청 동안 원본 링크가 보이며, 앞뒤 문단을 편집하면 범위를 추적합니다. 해당 URL 변경·삭제·undo·편집기 종료는 늦은 삽입을 취소합니다. 변환 후 undo는 원본 링크로 되돌립니다.
- SNS HTTP 거부·제목 없는 응답·서비스 이름뿐인 응답은 빈 성공 카드로 꾸미지 않습니다. 자동 처리 실패는 URL 1개를 유지하고, 모달은 재시도/원본 링크 삽입을 제공합니다. SNS는 공개 메타데이터 카드이며 공식 SNS 위젯 전체가 아닙니다.
- 실제 글 235에서 직접 입력 YouTube 1개·X 공개 게시물 카드 1개·제한 주소의 원본 링크 1개를 저장→조회→재편집하여 확인했습니다. 비공개 SNS를 우회하거나 메타데이터를 생성하지 않습니다.
- 자동 회귀 119건과 기존 독립 Chromium E2E 21건 통과(15건은 뷰포트 비대상/미설정 G7 환경 skip, 통과에 포함하지 않음). 최종 후보에서 재검증합니다.
- 이번 결함을 다시 놓치지 않도록 `functional-audit.json`을 기존 62개 gate에 추가 연결했습니다. 실제 이미지·서버 빈 본문·MP4 재생 시간·URL 실패/성공과 새 screenshot/후보 ZIP이 없으면 통과하지 않습니다.
- RC1 공개 ZIP은 보존하며 새 후보는 `0.1.0-rc.2`입니다. 후보 검증·패키지·배포는 아래에 별도로 기록합니다.

### 최종 검증에서 발견한 다국어 저장 누락

RC2 실제 상품 검사에서 한국어 입력 직후 영어 탭 입력·저장을 하면 이전 한국어 수정이 사라졌습니다. 같은 필드의 모든 언어가 하나의 debounce 키를 사용한 것이 원인이었습니다. 언어별 키를 분리하고 실제 G7 엔진의 빠른 전환/즉시 저장·리사이즈·빈 번역 회귀 3건을 추가했습니다(상태 동기화 총 10건).

수정 후 실제 상품 101의 빠른 한영 전환·즉시 저장·재조회에서 두 언어가 모두 보존됐습니다. RC2는 원격에 배포하지 않았고 ZIP을 덮어쓰지 않습니다. 수정 후보 `0.1.0-rc.3`을 새로 패키징하여 다시 검증합니다. 이 보완은 4차 완료 검사 중 발견한 결함 수정입니다.

## 배포

미실행. 네 차수의 검증과 같은 후보 ZIP의 staging 게이트를 통과한 뒤 승인된 배포 대상을 적용합니다.
