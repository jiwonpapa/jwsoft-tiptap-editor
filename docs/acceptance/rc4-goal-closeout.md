# RC4 Enter·외부 삽입 개선 진행 기록

목표: 제목 Enter 방어, X·Facebook 공식 화이트리스트 표시, 기존 미디어 편집/조회 동등성을 통합하고 현재 패키지 검증 후 두 승인 대상에 배포.

## 1차

- 커밋 `054d6a2`: 미처리 기본 GET 제출만 방어. G7 코어·번들 무수정.
- 단위 7건 및 실제 Chromium 데스크톱/모바일 제목 Enter 2건 통과.
- 제목 보존, 본문 필수 오류, 본문 포커스, 저장 버튼 Enter 동작 확인.
- 실제 로그인 G7 재검증은 아래 후속 차수에서 기록한다.

## 2차

- 정책 1.6.0 및 ADR-0014: 고정 X·Facebook URL/SDK/CSP 화이트리스트, 제공자별 토글.
- 편집/조회 동일 공식 표시기. canonical HTML에는 SDK/iframe/실행 DOM을 저장하지 않음.
- 공식 SDK의 opaque-origin sandbox 실험은 X CORS/Facebook 제약으로 실패하여 채택하지 않음. 현재 표시 프레임은 보안 sandbox가 아니며 외부 SDK 신뢰 위험을 명시.
- 모바일 삭제 검사에서 포커스 전환과 문서 변경을 한 chain에 넣으면 삭제되지 않는 경로를 발견. 문서 변경 후 포커스로 순서를 분리하고 3회 연속 통과. 영상 노드에도 동일하게 적용.
- `make check` 163개 단위 및 PHP/공급망/배포 계약 통과, 독립 Chromium 29개 통과·13개 비대상/실제 제공자 opt-in 제외.
- 실제 X 공식 게시물의 본문·사진, Facebook 공개 게시물의 본문·사진 표시 확인. 데스크톱/모바일 두 실행 통과. 조회·편집은 각각 화면 증거로 구분.
- 처음 사용한 Facebook 예제는 이용 불가 응답으로 실패했고 성공 증거에서 제외. 공개 게시물로 교체해 재검증했으며 오류 판정 기준은 유지.
- G7 설정·서버 whitelist descriptor·기존 SSRF 통합검사 통과. ZIP 설치/로그인 화면/배포 증거는 아직 별도 단계.

## 3차: 현재 ZIP의 실제 G7·Chrome 검증

- 공식 ZIP 업데이트로 설치한 RC4와 배포 JS 체크섬을 대조했다. 개발 overlay가 아니다.
- 실제 로그인 Chrome에서 제목 Enter: 공개/관리자 모두 제목 보존, 본문 오류 및 포커스, 새로고침 없음. 등록 버튼은 서버 본문 필수 검증을 유지한다.
- 공개/관리자 × 작성/수정/답글 × 빈 문단/보이지 않는 문자/빈 표의 HTTP 18건이 본문 오류 422로 거절됐으며 콘텐츠 해시가 보존됐다. 답글은 답글 허용 게시판의 실제 부모 글을 사용했다.
- 공개/관리자 이미지 업로드·저장·조회·재편집, 잘못된 PNG 거절 및 재시도 오류를 확인했다. Chrome 파일 선택은 네이티브 선택창으로 검증했고 브라우저 권한은 변경하지 않았다.
- MP4 원본 확장자, 12초 영상의 실제 재생 시간 변화, 206 Range, 저장/조회/재편집의 controls를 확인했다. YouTube는 클릭 대기 화면 없이 플레이어가 표시됐다.
- X 공식 본문·사진과 Facebook 공개 본문을 편집/저장/조회에서 확인했다. 이용 불가 URL은 원본 링크로 유지된다. 외부 제공자 정책·공개 상태·차단 환경에 따른 실패까지 성공으로 간주하지 않는다.
- 신규 게시글·관리자 글·답글·상품·페이지를 UI로 작성했고 재편집과 공개 조회를 확인했다. 상품/페이지 공개 API는 DB canonical HTML과 일치했다. 기존 QA 상품의 한국어/영어는 입력 약 0.12초 후 언어 전환·즉시 저장 회귀검사에서도 각각 보존됐다.
- 기본 알림 HtmlEditor 모달은 Tiptap 0개/textarea 1개를 유지하며 설정을 저장하지 않았다.
- 실제 Chrome 5개 편집 경로 준비 시간 378/650/386/405/407ms, 인스턴스 모두 1개. 390×844 다크 화면의 툴바/본문 가로 넘침 없음. 영문 접근성 레이블과 키보드 접근 가능한 도구를 확인했다.
- 현재 코드 기준 `make check`, 전용 G7 `make integration-check`, 독립 UI 29건 및 실제 공식 SNS 데스크톱/모바일 2건 통과. 비대상/별도 opt-in 13건은 통과 건수에 포함하지 않았다.
- 상세 증거: 로컬 `test-results/parity/browser/rc4-actual/`, 검증기가 생성하는 functional/browser/surface evidence. 원본 QA 외 콘텐츠 해시는 전후 대조한다.

## 4차: 설치 수명주기·배포

- 완료: 후보 공개 57/57 → GitHub 설치/업데이트/제거 후 데이터 보존 → staging 전 60/60 → production 전 61/61 → 최종 `make release-check` 62/62.
- 공식 ZIP RC3 → RC4 업데이트, CKEditor 복귀, JWSoft 재활성화에서 본문·이미지 기록 보존. GitHub URL 설치·업데이트도 RC4 실물로 재검증했다.
- 최초 GitHub 검사는 prerelease 제외 정책 때문에 RC3를 받아 실패했다. G7의 `/releases/latest` 조회와 기존 RC3 채널을 확인하고 RC4도 동일 배포 채널에 공개한 뒤 재검증했다. 버전과 릴리스 설명에는 RC 후보임을 유지한다.
- 승인된 로컬 도메인에 먼저 적용하고 smoke를 통과한 동일 ZIP을 온라인 SSH 대상에 적용했다. 두 곳 모두 JWSoft RC4 활성 / CKEditor 비활성. G7 코어·번들 및 다른 제품 코드는 수정하지 않았다.
- ZIP SHA256: `9258b950fb603a5b58c756aa1d62ea6d99ef674213213e045521c7dac6b09fa9`.
- 두 대상 각각 설치 파일 **178개 전체**가 ZIP과 일치하고 공개 JS에도 동일 빌드가 제공된다.
- 온라인 페이지/게시글/상품 **70,020개**의 본문 해시 보존, 로컬 대상 관련 **15개 테이블** 및 모듈 등록 상태 보존. DB/플러그인 백업은 원격과 호스트에 보관했다.
- 배포 후 Chrome에서 예전 `click` 설정이 남아 즉시 표시되지 않는 것을 확인했다. 승인된 즉시 표시 요구에 맞춰 **`externalMediaLoadMode` 하나만 `immediate`로 변경**, 자동재생 false 및 나머지 설정 보존을 대조했다.
- 온라인 기존 X 글의 본문·사진 즉시 표시, YouTube 실제 플레이어 즉시 표시, 기존 업로드 MP4의 60초 영상 재생 시간 0 → 13.25초 증가/오류 없음 확인. 기존 저장 본문을 재저장하지 않았다.
- 온라인 기존 Facebook 테스트 글은 `photo.php` 일반 링크로 저장돼 있어 그대로 유지된다. 공식 Facebook 삽입은 허용된 공개 `/posts/`, `/videos/` URL 범위이며, 이 제약과 기존 링크 미변환을 완료 보고에 명시한다.
- 전용 QA 계정 권한·토큰은 회수했고 검증 설정을 복원했다. 임시 테스트 서버와 QA Chrome 탭도 종료했다.
- 상세 배포 증거: 로컬 `.build/rc4-deploy-20260831.TT16Bm/summary.json`, 파일/콘텐츠/설정 전후 비교와 Chrome 화면. 공개 릴리스는 `v0.1.0-rc.4`이며 완벽한 모든 SNS 호환이나 Facebook 미지원 URL 성공을 뜻하지 않는다.
