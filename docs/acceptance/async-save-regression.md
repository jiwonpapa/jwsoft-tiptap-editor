# 비동기 확인 응답과 본문 저장 회귀 검증

2026-09-02, 전용 G7 7.0.9 호스트의 로그인한 독립 헤드리스 Chrome에서 확인했습니다.

## 재현과 책임 범위

1. 관리자 페이지 작성에서 슬러그 중복 확인을 누릅니다.
2. 응답을 기다리는 동안 제목과 본문을 입력합니다.
3. 확인 응답 이후 제목 필수 오류가 발생하면 제목만 다시 입력하고 저장합니다.

검사에서는 실제 슬러그 API 응답에 800ms 지연만 추가했습니다. 응답 본문·저장 API·서버 저장 로직은 모킹하지 않았습니다. 수정 전 화면의 본문은 남아 있었으나 저장 요청은 `content.ko: ""`, HTTP 201 응답은 `content.ko: null`이었습니다. 단순한 화면 측정 오류가 아니라 실제 데이터 누락입니다.

G7의 비동기 액션이 이전 폼 상태를 복원하는 경로는 제목에도 영향을 줍니다. 제목·슬러그·G7 코어를 에디터에서 수정하지 않습니다. 운영자가 사용할 수 있는 호스트 측 회피 절차는 중복 확인 완료 후 입력하는 것입니다. 제목까지 해결된 것으로 보고하지 않습니다.

## 에디터 보완

수정된 본문을 호스트의 버튼/submit 액션 직전에 공식 `G7Core.state.setLocal`로 다시 전달합니다. G7이 액션 처리 전에 pending debounce를 비우는 기존 계약을 사용합니다. 요청 가로채기, private 상태 조작, 코어·템플릿 수정은 하지 않습니다.

- 자기 필드와 언어만 동기화하며 제목·가격 등 다른 필드를 수정하지 않습니다.
- 읽기 전용·미수정·분리된 에디터, 다른 폼/모달, SPA 경로 변경 후에는 동기화하지 않습니다.
- 사용자 제출을 취소하거나 자동 저장하지 않습니다. 서버 정제·필수 검사도 유지합니다.
- 에디터 종료 시 이벤트 리스너를 제거합니다.

## 검증

- 단위검사: 저장 동작 전 순서, 읽기 전용, 미수정, 다른 폼/모달, 삭제, SPA 이동, 정리 7건.
- 실제 G7 엔진: 늦은 상태 복원 후 단일/다국어 본문 보존 2건을 기존 10개 시나리오에 추가.
- 로그인 화면: 일반, 같은 값 재시도 2건, 지연 응답 2건, 모바일 크기 변경의 총 6건에서 요청·응답·재편집 본문 일치. 지연 응답 2건은 G7이 비운 제목만 다시 입력했고 에디터 본문은 재입력하지 않았습니다.

원시 증거는 로컬의 `test-results/parity/browser/jw-final/page-delayed-title-retry.json`(수정 전 실제 저장 누락)과 `page-stress.json`(수정 후)입니다. 이것만으로 전체 릴리스 검증을 완료했다고 표현하지 않습니다.
