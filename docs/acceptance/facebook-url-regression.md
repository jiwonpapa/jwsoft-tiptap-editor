# Facebook URL 수정과 X 주소 지원 범위 점검

2026-09-02. **Facebook 주소 정규화·서버 회귀 검사는 통과했지만, 최신 실제 외부 표시 재검사는 일부 실패했습니다. 전체 완료·안정판 승인·온라인 배포 결과가 아닙니다.**

## 수정한 결함

1. 기존 Facebook 정책은 계정별 `posts`·`videos` 경로만 허용했습니다. 제보된 `photo/?fbid=`의 식별자를 인식하지 못했습니다. 사진, 고유링크, Story, Watch, Reel을 클라이언트·서버 공통 정책 1.6.1로 정규화합니다. 중복·잘못된 식별자와 위장 호스트는 거부합니다.
2. 공유 주소는 공식 SDK에 그대로 전달해도 표시되지 않았습니다. `share/p|v|r/토큰`·`fb.watch/토큰`은 서버의 공개 IP 검증·DNS 고정·제한된 HEAD 리다이렉트로 원본 허용 Facebook 게시물을 확인한 경우에만 변환합니다. 로그인·다른 호스트·루프·연결 실패는 성공으로 처리하지 않습니다.
3. Laravel의 기본 throttle 키는 경로가 아니라 사용자와 prefix를 사용했습니다. G7의 일반 관리자 요청과 미리보기의 10회/분 카운터가 충돌하여 첫 미리보기도 429가 될 수 있었습니다. 플러그인 전용 prefix로 분리했고 11번째 요청은 여전히 차단합니다. G7 코어는 변경하지 않았습니다.
4. 프로필·목록·확인 불가능한 공유 URL은 구체적인 안내를 반환하고 원문 링크를 유지합니다. 임의 iframe·스크립트를 저장하거나 Facebook의 공개 범위·로그인 제한을 우회하지 않습니다.

## 직접 찾은 실제 주소와 관찰 결과

독립 헤드리스 Chrome과 전용 G7 테스트 체크아웃을 사용했습니다. 사용자 브라우저·Page Builder·운영 서버는 사용하거나 변경하지 않았습니다. URL 변환, 저장, 제공자 표시, 실제 영상 재생을 구분했습니다.

공유 주소는 [University of Kentucky SCAHIP](https://scahip.uky.edu/outreach)와 [City of Pocatello](https://pocatello.gov/m/NewsFlash/Home/Detail/2459)의 공개 안내에서 직접 찾았습니다. 일반 게시물 주소는 제공자가 표시한 원문 링크로 확인했습니다.

모바일 QA에서 축소된 중첩 iframe의 자동화 클릭 좌표가 화면 밖 또는 다른 컨트롤을 가리키는 문제를 확인했습니다. 실제 버튼의 화면 좌표와 가시 범위를 확인한 포인터 클릭으로 재검사했으며, `video.play()` 호출로 재생 성공을 대신하지 않았습니다. 모바일 사진은 제공자가 낮은 해상도로 내려주므로 500px 이상이라는 초기 검사 기준을 실제 콘텐츠 이미지의 로드 여부로 정정했습니다.

## 최신 외부 표시 실패 — 통과 결과와 분리

최종 후보를 설치한 뒤 재검사에서 Facebook 공식 `plugins/post.php`가 **302 → `/login/` → HTTP 400, `X-Frame-Options: DENY`**를 반환했습니다. 제보 사진의 재편집 표시와 기존 Facebook live E2E가 실패했고, 화면의 다시 시도도 복구되지 않았습니다. X 표시와 원문 링크·실패 안내는 남았습니다.

이는 현재 관찰한 제공자 응답이며, 빈도 제한·지역·공개 범위 중 어느 원인인지는 확정하지 않았습니다. 이전의 성공을 최신 재검사 성공으로 바꾸지 않습니다. 로그인 강요 우회·임의 SDK 대체·정책 완화는 하지 않았습니다.

- `make check`: 단위 **237/237**, PHP 정제·정적 검사 통과.
- `make integration-check`: G7 연동 7개 suite, 상태 동기화 12개 시나리오 통과. Facebook 공통 fixture 50개, 안전한 공유 리다이렉트·연결 오류·실제 throttle 충돌/분리 검사 포함.
- 초기 브라우저 실행: **39 통과 / 11 viewport 조건 skip**.
- 최신 브라우저 실행: **37 통과 / 2 Facebook live 실패 / 11 viewport 조건 skip**. 실패를 제외하여 전체 성공으로 보고하지 않습니다.
- 최신 후보 ZIP SHA-256: `c210fde19c349abb4e0c07941980d51ac5447c9b70da33c8e2d8f226cc6722ba`.
- JS SHA-256: `1161ad164186ce01393b3d4ceee62ce1d301087dc8788b2c12f7c9afef162522`.
- 변경된 런타임 10개 파일의 소스·ZIP·전용 호스트 SHA가 일치합니다. 최신 ZIP의 성공 경로는 앞서 검사한 후보와 같고 연결 실패의 명시적 안내 처리가 추가됐지만, 앞선 실제 표시 성공 기록을 최신 ZIP의 전체 통과 증거로 대체하지 않습니다.
- 원시 기록: `output/playwright/facebook-photo/`의 유형별 JSON·PNG·`runtime-hashes.json`, `test-results/playwright/`의 실패 trace. 테스트 자료는 로컬 산출물이며 배포 파일에 포함하지 않습니다.

## X는 모든 주소를 지원하지 않음

현재 서버 정규화기에 16개 형태를 직접 입력해 **8개 허용 / 8개 미지원**을 확인했습니다. 별도의 live 브라우저 검사에서 일반 게시물의 본문·이미지는 표시됐습니다. 모든 형태의 실제 게시물을 개별로 저장·재생했다는 뜻은 아닙니다.

| 주소 유형                                                        | 현재 공식 게시물 삽입     |
| ---------------------------------------------------------------- | ------------------------- |
| `x.com/계정/status/ID`, `twitter.com/계정/status/ID`             | 지원                      |
| `www.x.com`, `www.twitter.com`, `mobile.twitter.com`의 같은 경로 | 지원                      |
| `x.com/i/status/ID`, `x.com/i/web/status/ID`                     | 지원                      |
| 위 주소의 끝 `/`, `?s=20&t=...`, `#...`                          | 추적 부분을 제거하고 지원 |
| `.../status/ID/photo/1`, `.../status/ID/video/1`                 | 미지원                    |
| `.../계정/statuses/ID`                                           | 미지원                    |
| `mobile.x.com/계정/status/ID`                                    | 미지원                    |
| `t.co/토큰`                                                      | 미지원                    |
| 프로필, Spaces, `intent/tweet`                                   | 게시물 임베드 대상이 아님 |

HTTPS의 고정 호스트·게시물 식별자만 허용합니다. 다음 X 확장은 실제로 복사되는 사진/영상 상세 URL을 원래 게시물로 정규화하고, 단축 URL은 최종 허용 게시물임을 확인하는 범위가 적절합니다. 현재 작업에서는 X 실행 정책을 임의로 확대하지 않았습니다.

## 배포 판정

소스 수정·테스트 후보 생성·전용 호스트 설치까지 수행했습니다. GitHub 공개·운영 배포는 하지 않았습니다. 이전 후보의 57/57 gate는 이번 수정본에 재사용할 수 없습니다. 외부 표시 실패 재확인과 미완료 주소 유형의 실제 저장·표시 검증 후 현재 패키지에 대한 릴리스 절차를 다시 진행해야 합니다.
