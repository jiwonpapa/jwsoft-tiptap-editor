# RC1 실제 G7 설치 검증 — 배포 차단

2026-08-30, `0.1.0-rc.1`. 로컬 설치는 완료했으나 **신규 게시글의 반응형 전환 후 본문 유실이 재현돼 공개·운영 승격을 중단**했습니다. 코어 또는 번들 모듈의 구현은 수정하지 않았습니다.

## 설치와 원본 보존

- 소유자가 승인한 공유 로컬 G7을 공식 업데이트로 `7.0.8 → 7.0.9` 전환했습니다.
- DB 전체 및 업로드·환경 파일을 먼저 백업했고, 공식 코어 업데이트 백업도 보존했습니다. 환경 파일·백업·서버 정보는 커밋하지 않습니다.
- 공식 업데이트의 단계 실행이 오래된 개발 패키지 캐시 때문에 중단되어, 공식 `core:execute-upgrade-steps`로 재개했습니다. 오래된 버전 캐시를 재생성하고 장기 실행 프로세스를 재시작한 뒤 7.0.9와 단일 에디터 활성 상태를 확인했습니다.
- 검증한 ZIP SHA-256: `98e8b070ed2a8fd34487bf1399cee02aceba3337cf807d7cfdeed34c78bde7bc`.
- 기존 페이지 6개 본문과 Page Builder 소유 12개 테이블의 전체 데이터 해시가 설치·검증 전후 동일합니다. 기존 콘텐츠는 수정하지 않았습니다.
- QA 전용 게시판 1개, 게시글 6개, 페이지 1개, 업로드 이미지 1개만 추가했습니다. 재현 자료로 남기고 임시 QA 계정 권한은 검증 후 회수합니다.

## 실제 관찰

| 흐름 | 결과 |
| --- | --- |
| 페이지 작성 → 이미지 모달 업로드 → 저장 → 재편집 → 관리자/공개 출력 | 통과 |
| 관리자 게시글 작성 → 서식 저장 → 재편집 → 출력 | 통과 |
| 공개 게시글 재편집 → 답글 → 출력 | 통과 |
| 새 공개 글 작성 → 테마만 전환 → 저장 | 본문 보존 |
| 기존 QA 글 수정 → 화면 너비만 전환 → 저장 | 본문 보존 |
| 새 공개 글 작성 → 412×915로 변경 → 데스크톱 복귀 → 저장 | **실패: 화면 본문은 남으나 `<p></p>` 저장** |
| CKEditor 1.0.2에서 같은 신규 작성·너비 전환·저장 | **실패: 화면 본문은 남으나 ‘내용은 필수입니다.’ 오류** |

처음에는 테마 변경과 너비 변경을 함께 수행해 테마 문제로 의심했으나, 독립 비교에서 신규 작성의 너비 전환으로 조건을 좁혔습니다. 최초 빈 본문 재현 2회에 이어 너비 단독 변경에서도 재현했습니다. CKEditor 비교 중에는 JWSoft를 비활성화했으며, 두 replace 에디터를 동시에 활성화하지 않았습니다.

다크모드 412px 화면에서 툴바 가로넘침이 없는 것은 관찰했지만, 저장 회귀가 있으므로 반응형 전체 통과로 처리하지 않습니다. 이 결과는 브라우저 뷰포트 검증이며 모바일 실기기 검증이 아닙니다.

## 원인 판단의 경계

두 에디터는 G7의 공개 `state.setLocal`을 `debounce`, `render:false`, `selfManaged:true` 옵션으로 사용합니다. 같은 호스트에서 CKEditor도 실패한 점은 공통 상태 동기화 경로의 문제를 시사합니다. 그러나 현재 비교에는 Page Builder 공개 셸이 포함되어 있으므로 **G7 코어 단독 결함으로 확정하지 않습니다**. 기본 셸 격리와 요청 시점의 상태 재현이 추가로 필요합니다.

JWSoft에서 빈 HTML이 실제 저장된 결과 역시 별도 결함입니다. CKEditor에도 문제가 있다는 이유로 JWSoft의 실패를 동등성 통과로 간주하지 않습니다. 공통 상태 보존과 빈 본문 저장 차단을 모두 검증해야 합니다.

## 배포 및 후속 범위

- 실패 smoke 후 JWSoft는 설치 상태로 비활성화하고 CKEditor를 다시 활성화했습니다. CKEditor 역시 위 반응형 재현 경로는 정상 판정을 받은 것이 아닙니다.
- RC GitHub 공개·원격 staging·production 적용은 수행하지 않았습니다. 이전 배포 ZIP을 교체하거나 실패한 기록을 pass로 바꾸지 않았습니다.
- 상품·다국어·fallback 및 나머지 출시 검증은 이 차단 사항 해소 후 다시 수행합니다.
- 에디터 프로젝트의 코어 무수정 원칙에 따라, 필요하면 별도 승인된 G7 연동 작업에서 기본 셸 격리 → 공통 원인 수정 → 공식 산출물 적용을 진행합니다. 에디터에서 G7 내부 상태를 조작하는 우회는 넣지 않습니다.
- 재개 게이트: 두 에디터 각각 신규 글의 데스크톱↔모바일 전환 후 본문 보존, JWSoft 페이지/상품/다국어 회귀, 현재 패키지의 후보 57개 → 사전 60개 → staging 61개 → production 62개.

실제 관찰 JSON과 스크린샷은 Git 비추적 `test-results/parity/browser/g7-local-rc-validation-blocker.json` 및 같은 폴더에 보관합니다. 이 문서는 출시 통과 증거를 대신하지 않습니다.
