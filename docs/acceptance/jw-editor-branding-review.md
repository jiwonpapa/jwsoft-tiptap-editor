# jw-editor 0.1.1 배포 전 검증 결과

2026-09-02, 현재 후보 ZIP의 내부 검증은 **57/57 통과**했습니다. 배포 전 필수 60개 중 GitHub 실제 설치·업데이트·삭제 3개는 아직 미완료입니다. 정식 출시·운영 배포 완료 보고가 아닙니다.

## 구현

- 사용자 표시 이름 `jw-editor`, 하단 왼쪽 버전과 도움말 버튼, 한영 도움말 모달.
- 현재 편집 내용의 정제된 HTML을 읽기 전용으로 조회·복사. 원문 HTML 편집 기능이 아닙니다.
- 기본 편집·이미지·표·미디어·SNS 내부 확장 조립 구조. 외부 모듈을 런타임 설치하는 SDK는 아닙니다.
- Apache-2.0, NOTICE, 제3자 고지, 패키지 라이선스 일치 검사.
- README 소개·설치·범위·개발 문서. 인트로는 편집 문서가 중심이며 회사 캐릭터는 문서 내부의 작은 선택 이미지로 배치했습니다. `지원` 한글은 제거했습니다.
- 플러그인 식별자·저장소 주소·네임스페이스·DB·canonical HTML 정책은 유지합니다.

- 전용 G7 체크아웃의 `make integration-check`: 7개 suite와 상태 동기화 12개 시나리오를 통과했습니다.

- 독립 헤드리스 Chrome의 로그인한 G7 화면에서 도움말을 데스크톱/모바일 × 밝은/다크 4조건으로 확인했습니다. 모달 넘침 없음, 읽기 전용 소스, Escape 포커스 복귀, 본문 무변경을 확인했습니다.

- 별도 QA 게시글에 빈 본문 HTTP 검사 18건을 실행했고 기존 게시글 본문 해시가 유지됐습니다.
- MP4 실제 업로드 → 삽입 → 저장 → 재편집·공개 출력·모바일 재생을 확인했습니다. 원본은 180×320이며 모바일 표시 310×551, 화면/본문 너비 390px으로 넘침이 없었습니다. 편집/출력 모두 controls가 있고 실제 재생 시간이 진행했으며 Range 요청은 HTTP 206이었습니다.
- YouTube 직접 입력, X 주소, 미지원 URL의 원문 링크 유지, 미리보기 실패 HTTP 422 및 저장 후 재열기를 확인했습니다. 실행용 iframe/SDK DOM은 저장 정본에 포함되지 않습니다.
- 답변 저장·재편집, 페이지 생성·수정·관리자/공개 출력, 상품 작성 화면의 에디터 표시와 기존 상품 한·영 설명 저장·재편집·공개 출력을 확인했습니다. 상품 자체의 신규 생성 성공을 뜻하지 않습니다.
- 에디터 설정 13개 상태와 새로고침 후 유지, 5개 주요 진입 화면의 단일 인스턴스, `directHtmlEditor`의 textarea fallback을 확인했습니다.
- 실제 API 응답과 DB의 canonical HTML 일치, 제공된 번들에 현재 JS가 정확히 포함됨을 확인했습니다.
- 공식 ZIP 업데이트 `0.1.1-rc.2 → 0.1.1`, 동시 에디터 활성 차단, CKEditor 복귀 후 jw-editor 재활성화가 통과했습니다. 페이지·게시글·상품 본문 해시와 업로드 기록이 보존됐습니다. 최종 전용 호스트는 jw-editor 0.1.1 활성 / CKEditor 비활성입니다.
- `make parity-gate`: 동등성 22개 기준 통과. 현재 입력·런타임·ZIP에 결합한 후보 gate는 **57/57**입니다.

## 검사 중 발견해 수정한 결함

페이지 슬러그 확인의 늦은 응답이 호스트 폼 상태를 이전 값으로 되돌린 후, 화면에는 남은 본문이 빈 값으로 제출되는 결함을 재현했습니다. 수정 전 실제 저장 응답은 HTTP 201 / `content.ko: null`이었습니다.

편집한 자기 본문을 호스트 액션 직전 공식 상태 API로 다시 전달하도록 보완했습니다. G7 코어·템플릿이나 제목·가격 필드는 변경하지 않았습니다. 일반·재시도·지연 응답·크기 변경의 6건에서 요청 → 응답 → 재편집 본문이 일치했습니다. 지연 검사에서는 제목만 다시 입력했고 본문은 재입력하지 않았습니다. 자세한 내용은 [비동기 저장 회귀 검증](async-save-regression.md)에 기록했습니다.

## 검증 경계와 별도 호스트 관찰

- 전용 G7 7.0.9 테스트 호스트와 독립 헤드리스 Chrome만 사용했습니다. 사용자의 브라우저나 Page Builder 작업은 사용하지 않았습니다.
- G7은 기본 `HeadlessChrome` HTTP User-Agent를 크롤러로 분류해 스크립트 없는 SEO HTML을 반환합니다. 사람용 화면 검사는 HTTP User-Agent만 Chrome으로 지정했고, 브라우저 자체는 계속 헤드리스였습니다. 이를 MP4 결함이나 로그인 실패로 판정하지 않았습니다.
- G7의 늦은 응답이 제목을 비우는 문제는 에디터 수정 범위 밖이며 남아 있습니다. 슬러그 확인 완료 후 입력하는 회피 절차를 별도로 기록했습니다.
- G7 상품 복사 시 가격 문자열의 정수 검증 422를 관찰했고, 별도의 신규 상품 옵션 생성은 완료하지 못했습니다. 상품 작성 화면 표시와 기존 상품 설명 저장 검증을 이 전체 생성 흐름의 성공으로 확대하지 않습니다. 가격·옵션의 근본 원인 분석/수정도 이 결과에 포함하지 않습니다.
- 테스트 계정 권한·토큰을 회수하고 임시 비밀번호 파일을 삭제했습니다. 독립 테스트 브라우저와 이 작업의 테스트 서버를 종료했습니다. 검증용 데이터와 원시 증거는 보존했습니다.
