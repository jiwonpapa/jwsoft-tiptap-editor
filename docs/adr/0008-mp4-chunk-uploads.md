# ADR 0008 — MP4 청크 업로드

- 상태: Accepted
- 날짜: 2026-08-28
- 적용 버전: 0.1.0-alpha.9

## 배경

MP4를 일반 multipart 요청 한 번으로 올리면 PHP 요청 크기와 네트워크 실패 지점이 파일 전체로 확대됩니다. 반대로 브라우저 조각만 신뢰하면 누락·순서 변경·변조된 조각이 완성 파일에 섞일 수 있습니다.

## 결정

- `videoUpload`은 기본 꺼짐이며 서버 FormRequest도 같은 설정으로 요청을 차단합니다.
- 서버가 청크 크기와 개수를 결정하고 128-bit 임의 세션 토큰을 발급합니다.
- 각 청크는 정확한 예상 길이와 SHA-256을 검사하고, 같은 번호·같은 해시 재전송만 멱등 허용합니다.
- 브라우저는 네트워크·5xx 실패를 최대 3회 재시도하고 `sessionStorage`의 토큰으로 같은 탭에서 수신 완료 청크를 건너뜁니다.
- 완료 시 서버가 저장소의 청크를 순서대로 임시 스트림에 조립한 뒤 전체 크기, `ftyp` box, major brand, 실제 `video/mp4` MIME을 재검사합니다.
- 완성 파일과 세션은 각각 `jwsoft_tiptap_media_uploads`, `jwsoft_tiptap_media_upload_sessions`에 기록합니다. DB 기록 실패 시 완성 파일을 삭제합니다.
- 미완료 세션은 24시간 뒤 매시간 실행되는 정리 명령의 대상입니다.

## 결과

대용량 업로드 실패 비용과 PHP 메모리 사용을 청크 크기로 제한할 수 있습니다. 추가 DB 테이블 두 개와 업로드·서빙 API 6개, 정리 스케줄이 공개 계약에 포함됩니다. 브라우저 종료 뒤 자동 재개와 여러 기기 간 재개는 별도 영구 업로드 큐 없이는 지원하지 않습니다.
