# ADR 0012 — 동일 ZIP의 단계별 검증·운영 승격

- 상태: Accepted
- 날짜: 2026-08-30
- 적용 버전: 0.1.0-rc.1
- 승인: 제품 소유자 “1,2,3 승인 프로덕트 배포도 동일해”

## 배경

기존 규칙은 stable 태그 이후 배포를 요구하는 동시에 stable 게이트에 production 완료 증거를 요구해 순환했습니다. GitHub 주소 설치는 공개된 최신 릴리스가 있어야 그 버전을 검증할 수 있습니다. 패키지를 만들기 전에 그 패키지 설치 증거를 요구하는 순환도 제거해야 합니다.

## 결정

P0 62개를 삭제하거나 pass로 추정하지 않고 수행 가능한 순서로 나눕니다.

| 단계               | 필수 증거                     | 아직 완료가 아닌 항목                             |
| ------------------ | ----------------------------- | ------------------------------------------------- |
| 후보 공개 전       | 현재 ZIP·실제 G7 화면 등 57개 | GitHub 최초 설치/업데이트/uninstall 3개, 배포 2개 |
| staging 적용 전    | GitHub 수명주기 포함 60개     | 배포 2개                                          |
| production 적용 전 | 동일 ZIP staging 포함 61개    | production 1개                                    |
| 최종 승인          | 전체 62개                     | 없음                                              |

검증 버전은 `0.1.0-rc.1`로 고정합니다. alpha/beta는 production 금지를 유지하고 RC는 소유자 승인·60개 사전 증거·동일 checksum staging·production 토큰을 모두 충족할 때만 운영에 적용합니다. RC 62/62 승인은 해당 RC ZIP의 검증 완료이며 `0.1.0` 버전 검증이나 태그가 아닙니다. 정식 SemVer 버전으로 변경하면 새 입력을 다시 검증해야 합니다.

후보 ZIP 생성은 로컬 준비 작업이며 배포 권한이 아닙니다. `release-candidate-check`는 57개 후보 gate, `deployment-gate`는 환경에 따라 60/61개 gate, `release-check`는 재빌드 없이 현재 증거와 ZIP의 62개 최종 gate를 검사합니다. 알 수 없는 단계, 오래된 증거, dirty tree, 다른 ZIP은 차단합니다.

G7의 Latest 조회에 필요한 후보 공개는 기존 개발 채널과 같이 후보임을 명시합니다. 후보 공개 후 실제 GitHub 설치·업데이트·데이터 보존 uninstall을 실행해 나머지 3개를 채우며 과거 버전 증거로 대체하지 않습니다.

## 같은 서버의 승인된 단계 전환

제품 소유자가 staging과 production의 동일 대상을 승인했습니다. 실제 접속 정보는 gitignore된 환경 파일에만 둡니다. 동일 대상 여부는 SHA-256 지문과 `SAME_TARGET_PROMOTION_APPROVED=1`로 기록합니다. production 적용은 staging의 JSON 해시·버전·ZIP 해시를 재검증하고 새로운 적용 시각과 smoke를 기록합니다. 기존 단계 기록은 history로 보존합니다. 같은 서버이므로 환경 격리 검증으로 표현하지 않습니다.

## 보안·호환성·마이그레이션 영향

- 서버 정제, 허용 HTML, 업로드 인증, SSRF 방어, 단일 에디터 활성 조건은 변경하지 않습니다.
- G7 코어, 기존 저장 본문과 DB 정본을 수정하지 않으며 새 DB migration은 없습니다.
- 배포 전후 런타임 파일과 본문 해시를 대조하고 실패 시 CKEditor 복귀 절차를 유지합니다.
- production `--apply`·확인 토큰과 동일 ZIP 검사를 유지·강화합니다. 단계별 통과는 전체 통과와 구분합니다.
- 테스트 계정·문서는 전용 G7에서만 사용하고 비밀값·서버 주소는 커밋하지 않습니다.

## 검증

단계별 57/60/61/62 분리, 알 수 없는 단계 거부, alpha/beta production 거부, 같은 대상 미승인 거부, 다른 버전/ZIP 거부, staging 기록 변조와 적용 순서, 원격 변경 전 gate 실행을 회귀 검사합니다. 최종 완료는 `test-results/release/stable-readiness.json`의 실제 62/62 결과로만 판정합니다.
